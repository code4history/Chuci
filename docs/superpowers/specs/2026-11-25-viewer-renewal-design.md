# Chuci／Quyuan のスライダーとビューアの作り直し（設計）

- 日付: 2026-11-25
- ブランチ: Chuci・Quyuan とも `viewer-renewal`（master 起点の独立ブランチ。12 月トレインには入れない）
- 対象: Chuci（本体）と Quyuan（Chuci を継承する薄い包み）
- 決定者: 人間（2026-11-25 の対話で決定）。「私の判断」と書いたものは設計者の判断で、人間の確認をまだ受けていない

## 1. 目的と理由

Chuci と Quyuan の役割は、メディアのサムネイルをスライダーに並べ、選ばれたメディアを全画面のビューアで見せることである。今回の作り直しには理由が二つある。

1. **Swiper の版上げへの追随が負担になっている。** 必要な機能の使い方が版ごとに変わる。現状は 12 で、遠隔の最新版は 14（2026-10-30）。
2. **ビューアの操作感がメディアごとに違う。** ビューアを外部から借りているため、背景を黒にそろえて全画面に出しても差が残る。人間が挙げた具体的な差は次のとおり。
   - 起動時の振る舞い（「Loading...」などの出方）
   - 表示時の背景（3D メッシュだけ灰色の #303030、ほかは黒）
   - 3D 系の操作感（three.js の OrbitControls・gsplat の OrbitControls・A-Frame の look-controls で、移動や拡大の感覚が違う）
   - デバグ表示（3D メッシュは素の英文、Gaussian は絵文字入りの別の文面。項目も位置も違う）
   - 同じ動画なのに初期サイズが違う（MP4 は縦横比のまま、YouTube は枠いっぱい）

目的は、**メディアの性質上どうしても違う操作感を除き、全ビューアを同じデザインの文法で表示すること**である。

## 2. 目標・非目標・反目標

### 目標
- スライダーを自作し、Swiper への依存をなくす。
- 2D 画像（viewer.js）と 360 度（A-Frame・CDN 読み込み）を自前の実装に替える。Gaussian の描画は gsplat から Spark に替える。
- 全ビューアで、外枠・背景・読み込み中の表示・エラー表示・デバグ表示・前後の移動・キャプションと点の列の表示を共通にする。
- 3D 系（3D メッシュ・Gaussian・360 度）と 2D 画像の手の操作を、一つの規則にそろえる。
- サムネイルを元のメディアから作る API を用意する。閲覧時は IndexedDB に保存し、作成時は外部のツールから呼べるようにする。
- キャプションと点の列が重ならないようにする（スライダー：S1、ビューア：V2）。

### 非目標（今回はやらない）
- MaplatEditor への組み込み（作成時のサムネイル生成・保存・`thumbnail-url` への書き込み・既存データへの一括適用）。今回は API を用意し、動くことを確かめるところまでとする。
- 動画の再生バーを自前で作ること。MP4 はブラウザ標準、YouTube は YouTube のものを使う。
- 2D 画像の回転・反転。
- 360 度の初期の向きを指定する新しい属性。追加すると MaplatCore の許可リストの変更を伴うので、今回は扱わない。
- スライダーの見た目を全画面ビューアの見た目へ寄せること。スライダーは地図のポップアップ内の部品なので、矢印の色などは今のままとする。

### 反目標（技術的に動いても、こうなったら失敗）
- 地図データに書かれた `qy-swiper` と `qy-swiper-slide` の記述が、そのままでは動かなくなること。公開済みの POI テンプレートが壊れる。
- 属性を書いていない既存データが、作り直しの前と違う初期表示になること（特に Gaussian と 3D メッシュ）。属性が今まで効いていなかったものを効くようにする件は 5.4 を参照。
- 新しい依存ライブラリの版上げに、また振り回される構造になること。
- 「ビューアごとに少しずつ違う」状態が、自前の実装の中で再発すること。共通部分を各ビューアにコピーするのではなく、外枠が一か所で持つ。

## 3. 制約

- **データの約束事を変えない。** タグ名 `cc-swiper`・`cc-swiper-slide`・`cc-viewer`・`qy-swiper`・`qy-swiper-slide`・`qy-viewer` は維持する。属性も維持する。スライドの属性は `image-url`・`image-type`・`thumbnail-url`・`caption`・`material-url`・`camera-position`・`camera-target`・`show-texture`・`fit-to-container`・`debug-mode`、スライダーの属性は `has-thumb`・`autoplay` である。これらは MaplatCore の無害化の許可リスト（`MaplatCore/src/sanitize-allowlist.json` の `slide` と `swiper`）に載っており、地図データにも直接書かれている。**読む属性を増やす場合は、許可リストの変更が要る**ので、今回は増やさない。
- `image-type` の値（`image`・`panorama`・`youtube`・`video`・`3dmodel`・`gaussian`）も維持する。
- CSS 変数 `--cc-slider-theme-color`・`--cc-slider-navigation-color`・`--cc-viewer-z-index` は維持する。
- 外部由来の値は**テンプレート補間で HTML に入れない**。今の実装の不変条件（`setAttribute`・`textContent`・`escapeCssUrl`・`utils/youtube-embed.ts` による YouTube URL の検証）を引き継ぐ。
- 利用側は Maplat と MaplatCore（`@c4h/quyuan` 経由）。Leaflet・OpenLayers・MapLibre のポップアップ内で動くこと。
- Chuci の規則 rule-0001（外形仕様が変わったら文書を追随させる）と rule-0002（UI の見た目が変わったらスクリーンショットを撮り直す）に従う。
- 別サイトに置かれたメディアの絵を canvas に取り出すには、配信元の CORS 許可が要る（ブラウザの制約）。

## 4. 作り方の候補と決定

### スライダー：**自作に決定**

| 案 | 長所 | 短所 |
|---|---|---|
| **1. 自作（採用）** | 外部の版上げに振り回されない。ビューアとの連携を最初から自分の形で作れる。ポップアップ内でタッチ操作が地図と取り合う問題を自分で制御できる | iOS Safari などでの手触りの調整を自分で詰める必要がある |
| 2. Embla Carousel の特定の版をソースごと取り込む | 慣性やループの実績ある動き | 他人のコード約 3 千行を抱える。Embla の作法に合わせる層が要る |
| 3. Swiper 12 を fork | 今の動きに最も近い | 巨大（約 3.8 MB）で、使わない機能が大半。保守の負担が最も重い |

採用の理由：必要な機能が「1 枚ずつ送る」程度に限られ、スライド数も多くないため。

### 3D 系の描画：**すべて three.js の上に載せる**（私の判断。人間に提示し、異論は出ていない）

- 3D メッシュは今のまま three.js。
- 360 度は A-Frame（CDN・iframe）をやめ、three.js の球に正距円筒画像を貼って描く。
- Gaussian は gsplat（2025-07 から更新なし）をやめ、Spark（`@sparkjsdev/spark`、three.js 上の Gaussian 描画、MIT）に替える。配布物が大きい（約 17 MB）ので、**Gaussian を開いたときだけ動的 import で読み込む**。
- この形にすると、カメラ操作・背景・デバグ表示・初期視点の撮影が一つの実装で済む。

### 2D 画像：**自前**（viewer.js をやめる。人間が決定）

### 動画：**外枠と初期サイズだけそろえる**（人間が決定。案 A）

### キャプションと点の列：**スライダーは S1、ビューアは V2**（人間が決定）

## 5. 設計

### 5.1 全体の構成

- 実体は Chuci に置き、Quyuan は今と同じく継承して `qy-` の名前を与える。Quyuan 固有の振る舞い（MutationObserver による再描画など）は必要な分だけ残す。
- ビューアは「**共通の外枠**」と「**中身の描画部（メディアごと）**」に分ける。外枠が持つものは、背景・閉じる・前後・キャプションと点の列の帯・読み込み中の表示・エラー表示・デバグ表示の欄・キーボード操作・帯の表示と非表示の制御である。描画部が持つのは、メディアの読み込みと描画、手の操作の受け付け、デバグ用の値の提供だけ。
- 手の操作の解釈（ドラッグ・ホイール・ピンチ・ダブルクリックを「回転・拡大・移動・初期化」に変換する部分）は**一つの部品**にまとめ、2D 画像と 3D 系の全描画部で共有する。速度・慣性・拡大の倍率などの定数は一か所に置く。
- スライダーとビューアは、**公開の口だけ**でつなぐ。今の `cc-viewer` は Swiper の内部（`swiper.slider.params.loop`・`slideToLoop`・`realIndex`）に直接触れているが、これをやめる。最低限の口は次のとおり。
  - スライダー → ビューア：「項目の一覧（URL・種類・属性・キャプション）・今の番号・ループの有無」を渡して開く。
  - ビューア → スライダー：「番号が変わった」という通知。スライダーはそれを受けて自分の位置を合わせる。
  - 口の具体的な名前と形は作る側に任せる。ただし Quyuan の `qy-viewer` からも同じ口で使えること。

### 5.2 スライダー（自作）

- 機能は今と同じ：前後の矢印、点の列（押すと飛ぶ）、サムネイル列（`has-thumb`）、自動送り（`autoplay`、5 秒、操作しても止めない）、2 枚以上ならループ、キーボード操作、キャプション、ドラッグ・スワイプで送る。
- 送りは**1 枚ずつスナップ**する。自由な慣性スクロールは作らない。
- ループは**スライドを複製せず**、位置の計算で回す。
- 「押した」と「ドラッグした」の区別は、移動量のしきい値で判定する。今の `isDragging` と時間差の手当てはやめる。
- 地図のポップアップ内で使うので、スライダー上の操作が地図に伝わってパンやズームが起きないようにする。横方向の操作は取り込み、縦スクロールは妨げない。
- サムネイル列（`has-thumb`）でも、5.6 のサムネイル（自動生成を含む）を使う。
- 見た目は今のままとする（矢印の色、白い背景）。ただしキャプションと点の列は S1 に変える（5.7）。

### 5.3 共通の外枠

- **背景**：全ビューアで黒（`#000`）。3D の描画部も、シーンの背景色に同じ値を使う（今の 3D メッシュの #303030 はやめる）。
- **コンテンツ領域**：画面いっぱい（ノッチなどの安全領域は避ける）。帯とボタンはその上に重ねる（V2）。今の「90%×85% の内側に描く」はやめる。
- **閉じる**：右上。**前後**：左右の中央。ボタンの見た目は全ビューアで共通。
- **キーボード**：← → で前後、Esc で閉じる。3D 系の描画部は矢印キーを使わない。
- **読み込み中**：全ビューア共通の表示を一つだけ用意する。言語に依存しないスピナーにする（私の判断）。描画部が「読み込み完了」を知らせるまで出す。今の「Loading...」の文字列は各ビューアから取り除く。
- **エラー**：読み込み失敗・非対応の形式・URL の検証失敗を、共通の表示で出す。
- **デバグ表示**（`debug-mode`）：外枠の左上に、等幅の文字で出す。描画部は「項目名と値の組」を渡すだけで、書式は外枠が決める。項目は全 3D 系で次にそろえる（私の判断）。
  - カメラの位置（3D メッシュ・Gaussian）または向き（yaw・pitch。360 度）
  - 注視点（3D メッシュ・Gaussian）
  - 視野角
  - 読み込みの状態
  - 操作方法の一行（5.5 の規則の要約。全ビューアで同じ文面）
  - 値は、`camera-position` と `camera-target` にそのまま書き写せる形式で出す。
- **スワイプでの前後移動**は、ビューア上では作らない。ドラッグは回転・移動に使うので、取り合いを避けるため（私の判断）。前後の移動はボタンとキーボードだけで行う。

### 5.4 各ビューア

| 種類 | 描画 | 備考 |
|---|---|---|
| `image` | 自前（DOM の img に変換をかける、または canvas。作る側に任せる） | 初期表示は枠に収まる最大の大きさ。回転・反転なし |
| `panorama` | three.js の球と正距円筒画像 | 初期の向きは、今の A-Frame 版（`<a-sky rotation="0 -90 0">`）と同じ絵になるように合わせる |
| `3dmodel` | three.js（OBJ と MTL。今と同じ） | 下の「今まで効いていなかった属性」を参照。テクスチャの表示切り替えボタン（今は 3D メッシュだけにある）は、メディア固有の操作として残し、外枠の共通デザインで描く |
| `gaussian` | Spark（動的 import） | 今の gsplat が読める形式（`SPLAT.Loader.LoadAsync` が読む `.splat`）を引き続き読めること。属性がないときは、今の gsplat の既定カメラと同じ初期視点を再現する（本物のデータで前後の絵を比べて確かめる） |
| `video` | `<video controls>`（ブラウザ標準の再生バー） | 初期サイズは「縦横比を保ち、領域に収まる最大」 |
| `youtube` | iframe（YouTube の再生バー） | 初期サイズは `video` と同じ規則。縦横比は 16:9 として扱う（私の判断。iframe からは取得できない）。`utils/youtube-embed.ts` の振る舞いは変えない。動画 ID が取れない https の URL も今と同じく iframe に入れ、そのサムネイルはアイコンにする |

**今まで効いていなかった属性**（私の判断：効くようにする。不具合の修正として CHANGELOG に書く）

今のコードでは、次の属性を読んでも表示に反映していない。
- Gaussian の `camera-position` と `camera-target`：読むだけで、カメラに適用していない（`cc-viewer-gaussian.ts` で gsplat の既定カメラのまま）。
- 3D メッシュの `show-texture`：開くたびに `true` へ戻している。
- 3D メッシュの `fit-to-container`：読んでいない。

作り直し後は、属性に書かれたとおりに効かせる。
- 属性がないデータの初期表示は、今と同じにする（反目標）。
- `fit-to-container` は、モデル全体が枠に収まるようカメラを自動で置く。`camera-position` と `camera-target` が書かれていれば、そちらを優先する。
- ビューアとサムネイル生成は、同じ初期化の処理を使う。

### 5.5 手の操作の規則（2D 画像と 3D 系で共通）

| 操作 | 2D 画像 | 3D メッシュ・Gaussian | 360 度 |
|---|---|---|---|
| 1 本指ドラッグ・左ドラッグ | 移動 | 回転（注視点の周り） | 見回す（掴んで動かす向き） |
| ホイール・ピンチ | 拡大縮小（指やカーソルの位置を中心に） | 寄る・引く | 視野角を変える |
| 2 本指ドラッグ・右ドラッグ | 移動 | 平行移動 | なし |
| ダブルクリック・ダブルタップ | 初期表示に戻る | 初期視点に戻る | 初期の向きに戻る |

- 慣性の強さ、回転速度、拡大の刻みは、全描画部で同じ定数を使う。
- 360 度で今使っている `reverseMouseDrag: true` の向きは、上の「掴んで動かす」と同じ向きになるよう確かめる。

### 5.6 サムネイルの生成と保存

- Chuci は**サムネイル生成の API** を公開する。入力はメディアの URL・種類・スライドの属性（初期視点など）・出力の大きさで、出力は画像の Blob。閲覧時と作成時で**同じ関数**を使う。そうすれば絵が一致する。
- 種類ごとの作り方：

  | 種類 | 作り方 |
  |---|---|
  | `image` | 縮小する |
  | `youtube` | YouTube が公開しているサムネイル画像の URL を使う（生成しない） |
  | `video` | 冒頭近くの 1 コマ |
  | `panorama` | **展開後の初期の向き**で描いた絵 |
  | `3dmodel`・`gaussian` | 初期視点で描いた絵 |

- **優先順位**：`thumbnail-url` があればそれを使う。なければ、IndexedDB に保存済みのものを使う。それもなければ、種類のアイコンを仮に出し、裏で生成する。
- **生成の順序**：今表示中のスライドを先に作り、残りは一つずつ順に作る。同時に複数を読み込まない。
- **保存**：IndexedDB の鍵は「メディアの URL＋サムネイルに影響する属性（`camera-position`・`camera-target`・`material-url`・`show-texture`）＋出力の大きさ＋生成処理の版」。容量に上限を設け、古く使われていないものから消す。上限の値は作る側に任せる。
- **失敗時**：CORS で絵を取り出せない場合などは、アイコンのまま表示する。失敗はそのページを開いている間だけ覚え、IndexedDB には残さない。
- **作成時の利用**：MaplatEditor などのブラウザ環境から同じ API を呼べるよう、エクスポートと文書を整える。360 度・3D・Gaussian は WebGL を使うので、Node だけの環境は対象外とする。
- 出力の形式（WebP か JPEG か）と大きさの既定値は作る側に任せる。
- YouTube も API の戻り値は Blob とする（公開サムネイルを取得して返す）。取得できない場合、閲覧時は公開サムネイルの URL をそのまま `<img>` に使う（私の判断）。
- Gaussian も、裏の生成の列に入れる。そのときに Spark を読み込む（私の判断。初回が重いことは人間が了承済み）。順序は、今表示中のスライドの後とする。

### 5.7 キャプションと点の列

**スライダー（S1）**
- キャプションの帯は画像の下に場所を取り、画像には重ねない。
- 帯の左にキャプション（1 行。はみ出したら省略記号）、右に点の列。
- 8 件を超えたら、点の列を「2 / 12」の数字に切り替える。
- `has-thumb` のときは、今と同じく点の列を出さない（サムネイル列が代わりを務める）。
- 帯の要否（私の判断）：
  - 2 件以上なら帯を出す（キャプションが空でも点の列のために出す）。
  - 1 件だけでキャプションもなければ、帯は出さない。
  - 1 件でキャプションがあれば、キャプションだけの帯を出す。

**ビューア（V2）**
- 下に帯を重ねる。中身はスライダーと同じ（キャプション＋点の列、または数字）。キャプションは省略せずに折り返す。行数の上限は作る側に任せる。
- **表示する時**：開いた時と、前後へ移った時。
- **隠す時**：コンテンツへの操作（ドラッグ・拡大・再生）が始まった時。何もしなければ 3 秒後にも隠す。
- **再表示する時**：ドラッグを伴わない 1 回のタップ、またはマウスの移動。
- 帯を隠すとき、前後と閉じるのボタンは薄くする（押すことはできる）。
- 動画：MP4 は `play` イベントで隠す。YouTube は iframe の中の操作が外から見えないので、フォーカスが iframe に移ったこと（`window` の `blur`）を「操作した」とみなす（作る側が別の手段を選んでもよい）。
- YouTube の iframe にフォーカスがある間は、← → と Esc が効かなくてもよい。画面上のボタンで前後・閉じるができればよい。読み込み中とエラーの表示は、iframe の読み込みと URL の検証までを対象とし、動画が再生できるかどうかまでは見ない（私の判断）。

**自動送り（`autoplay`）とビューア**：ビューアを開いている間は、スライダーの自動送りを止める。閉じたら、ビューアで最後に見た項目をスライダーに表示し、そこから自動送りを再開する（私の判断）。

### 5.8 互換性と版

- タグ・属性・CSS 変数は維持する（3 章）。
- 外に見える変化は三つある。見た目（帯・背景・ボタン）、依存ライブラリ（swiper・viewerjs・gsplat・A-Frame の CDN をなくし、Spark を追加）、`cc-viewer` の内部向けの口（`setSwiper`・`setCurrentSlideIndex`）の置き換え。
- 版は **Chuci 2.0.0・Quyuan 2.0.0** とする（私の判断）。どの月のトレインで出すかは、別途決める。
- 互換を保証する範囲は、3 章のタグ・属性・CSS 変数に加え、Quyuan の `qy-viewer` の属性（`currenttype`・`currentslideindex`）と CSS 変数 `--qy-viewer-z-index` まで（私の判断。費用が小さいため残す）。`cc-viewer-*` の個別要素を直接使う使い方と、`cc-viewer` の `open(url, type, attributes)`・`setSwiper`・`setCurrentSlideIndex` は保証しない。Maplat・MaplatCore のソースにはこれらの利用がないことを確かめてある（2026-11-25）。CHANGELOG に破壊的変更として書く。
- MaplatCore の許可リストは変えない前提。変える必要が出たら、作業を止めて報告する。

### 5.10 確認

- **人間が見るためのデモ**：一つのページで、全 6 種類のメディアを順に開けるようにする。比べたいのは、メディアを切り替えたときの外枠・背景・読み込み中の表示・帯の振る舞い・初期サイズ。地図のポップアップ（Leaflet・OpenLayers・MapLibre。Quyuan の既存ページ）でも動かす。作り直し前後のスクリーンショットを並べる。
- **単体試験**（vitest）：スライダーの番号計算（ループ・端）、帯の表示規則（5.7 の表）、サムネイル保存の鍵と優先順位。
- **ブラウザ試験**（Playwright。Quyuan の e2e）：
  - スワイプ・クリックの区別
  - ポップアップ内で地図が動かないこと
  - ビューアの前後移動とスライダー位置の同期
  - 帯の表示と非表示
  - サムネイル生成（CORS を許可する配信と、許可しない配信の両方）
  - Gaussian の既存データで視点が変わらないこと
- 動きの確認は、ゲートの緑だけで済ませない。画面写真や動画のコマを実際に見て確かめる。

## 6. 作る側に任せること

- 各部品のファイル分割、クラスとイベントの具体的な名前。

- サムネイルの出力形式・既定の大きさ・IndexedDB の容量上限。
- 慣性・速度・拡大の刻みの具体的な値（ただし一か所で定義する）。
- スピナーとアイコンの具体的な絵柄。

## 7. 設計者の判断（人間の確認を受けていないもの）

- 3D 系をすべて three.js に載せ、Gaussian を Spark に替える（提示済み。異論なし）
- 読み込み中の表示は文字なしのスピナー
- デバグ表示の項目と位置（左上・等幅）
- ビューア上ではスワイプでの前後移動を作らない
- YouTube の縦横比を 16:9 として扱う
- スライダーの帯の要否の規則（5.7）
- 版を Chuci・Quyuan とも 2.0.0 にする
- 今まで効いていなかった属性（Gaussian の `camera-position`・`camera-target`、3D メッシュの `show-texture`・`fit-to-container`）を効くようにする。属性のないデータの見え方は変えない
- 互換を保証する範囲（5.8）。`cc-viewer-*` の直接利用と `cc-viewer` の内部向けの口は保証しない
- ビューアを開いている間は自動送りを止める
- YouTube：動画 ID の取れない URL も今と同じく表示する。iframe にフォーカスがある間のキー操作は保証しない
- Gaussian のサムネイルも裏で生成する（その時点で Spark を読み込む）
